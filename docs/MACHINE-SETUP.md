# Reproducing this machine

Everything a different Mac needs to build, sign and ship this app the way the
current one does. Written 11 September 2026, because the machine it describes
may not be around for the next release.

⚠️ **No secrets are in this file, and none should be added.** It records
*where* credentials come from and *what shape* they are, never their contents.

## Changes made to this machine

Two, both outside the repository, both reversible.

### `~/.gradle/gradle.properties` — created

```properties
org.gradle.jvmargs=-Xmx2048m -XX:MaxMetaspaceSize=1024m
kotlin.daemon.jvmargs=-Xmx1536m -XX:MaxMetaspaceSize=1024m
```

Without it, `eas build --platform android --local` dies with `Metaspace` in
`:expo-modules-core:lintVitalAnalyzeRelease`. CI solves the same problem by
appending these to `android/gradle.properties` after prebuild (see
`.github/workflows/e2e.yml`), but a local EAS build generates that file inside
a temp copy, so there is nothing to append to. Gradle reads the user-level file
at higher precedence, so it reaches the build either way.

⚠️ **Kill stale daemons after changing it** — `pkill -f GradleDaemon` — or a
daemon already running with the old arguments serves the next build.

### An empty NDK directory — deleted

`~/Library/Android/sdk/ndk/27.0.12077973` contained nothing but
`.installer/.installData`: a download that began when the disk filled and never
finished. Gradle saw the directory, assumed the NDK was installed, and failed
every Android build with `[CXX1101] … did not have a source.properties file`.

Worth knowing as a *class* of problem: **a build that fails on disk space can
leave the SDK in a state that fails differently afterwards.** Look for
near-empty directories under `ndk/` before believing a stranger error.

## Credentials, and where they come from

Nothing here lives in the repository. All of it is gitignored.

| What | Where it comes from | Used by |
| --- | --- | --- |
| Android keystore | **EAS**, fetched per build | every Android build |
| iOS certificate + profiles | **EAS**, into a throwaway keychain | every iOS build |
| App Store Connect API key | **EAS** | `eas submit` |
| `google-services.json` | in the working tree, gitignored | Android Firebase |
| `GoogleService-Info.plist` | in the working tree, gitignored | iOS Firebase |
| Firebase service account | a JSON file outside the repo | `firebase appdistribution:distribute` |
| Play service account | not created yet | `eas submit --platform android` |

⚠️ **On a fresh machine, the two Google files must be restored by hand.** They
are not in git and not on EAS in a form a local build can read — the EAS
variables holding them are `--visibility secret`, which only EAS builders can
access. Without them a local iOS build fails at
`Could not get GOOGLE_APP_ID in Google Services file from build environment`,
which reads like a signing error and is not.

## Environment variables

None are exported in the shell profile. Every one of these is passed per
command, deliberately — see [COMMANDS.md](../COMMANDS.md).

```bash
# A local iOS build. The plist is gitignored, and `eas build --local` archives
# the project FROM GIT, so the copy it builds has no credentials. The path must
# be absolute: the build runs from a temp copy, and only an absolute path still
# points at the real file from inside one.
GOOGLE_SERVICE_INFO_PLIST_PATH="$PWD/GoogleService-Info.plist" pnpm build:ipa:local

# A local Android build. ANDROID_HOME is not exported anywhere, so it is passed
# here too.
ANDROID_HOME="$HOME/Library/Android/sdk" \
ANDROID_SDK_ROOT="$HOME/Library/Android/sdk" \
GOOGLE_SERVICES_JSON_PATH="$PWD/google-services.json" \
  pnpm build:apk:local

# The Play package-ownership APK, and ONLY that build. The token identifies the
# developer account and is deliberately not committed — this repository is
# public. Every build without it deletes the file instead of skipping, so the
# token cannot end up in a binary that ships.
ADI_REGISTRATION_TOKEN="…" pnpm build:apk:local

# Distributing to testers. The service-account JSON lives outside the repo.
GOOGLE_APPLICATION_CREDENTIALS="/path/to/service-account.json" \
  npx -y firebase-tools appdistribution:distribute <artifact> \
    --app "$(node -p "require('./google-services.json').client[0].client_info.mobilesdk_app_id")" \
    --groups testers --release-notes "…"
```

The Firebase **app IDs** are not secret and need no lookup: Android's is in
`google-services.json`, iOS's is
`/usr/libexec/PlistBuddy -c 'Print :GOOGLE_APP_ID' GoogleService-Info.plist`.

## Reading a signature without the keystore

The keystore is on EAS, so the usual `keytool -list -keystore` recipe does not
apply. Read the certificate out of an artifact instead:

```bash
keytool -printcert -jarfile <file>.aab            # AAB — has a JAR signature
~/Library/Android/sdk/build-tools/36.0.0/apksigner verify --print-certs <file>.apk
```

⚠️ `keytool` reads **nothing** from a modern APK: those carry only v2/v3
signatures, with no JAR signature to parse. It prints an empty result rather
than an error, which looks like a missing key and is not. Use `apksigner` for
APKs.

The upload certificate for `com.rogeriodocarmo.morse` is
`5907bdde…39bd52d9`. ⚠️ That is the **upload** key. Once Play App Signing is
active, anything validating the app as users receive it needs Google's **app
signing** certificate instead, from Play Console → Test and release → Setup →
App signing.

## Quotas worth knowing before planning a day

- **EAS builds are a shared credit pool**, not a per-platform allowance.
  Running it out blocks Android, iOS and tester distributions alike, and
  refuses builds before they start. It ran out on 9 September 2026 and resets
  **1 October**. `--local` is free and unaffected.
- **`eas submit` is free.** There is never a reason to rebuild in order to
  submit.
