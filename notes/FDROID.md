# F-Droid

How OmniMorse is packaged for [F-Droid](https://f-droid.org), why it looks the way it does, and
what is still the owner's to do. It follows Miroji's approach (`../mirror_app/docs/FDROID.md`)
and says where it departs from it.

F-Droid compiles every app from source on its own servers and signs it with its own key. Its
[inclusion policy](https://f-droid.org/docs/Inclusion_Policy/) forbids proprietary code in the
APK, names Firebase and Crashlytics outright, forbids an app downloading code outside F-Droid's
review, and wants a build flavour without such dependencies when upstream has them. Miroji had
none of those problems. OmniMorse has three, and most of this document is about them.

⚠️ Decision of 22 October 2026: **acceptance matters more than feature parity.** The F-Droid
build may lose features. Text-to-Morse is the floor. In practice it loses only crash reporting
and over-the-air updates, because nothing else F-Droid would reject turned out to be in the app.

## The three repositories

Same shape as Miroji's:

| Repository | Role |
| --- | --- |
| `morse_app` (this one) | The real project. The F-Droid variant lives here as ordinary app source. |
| `morse_app-android` | The build mirror F-Droid builds from: a plain-Gradle snapshot of the F-Droid variant, regenerated by `.github/workflows/android-mirror.yml`. **Does not exist yet.** |
| fork of `fdroid/fdroiddata` | Carries `metadata/com.rogeriodocarmo.morse.yml`. The draft is [fdroid/com.rogeriodocarmo.morse.yml](fdroid/com.rogeriodocarmo.morse.yml). |

## The build variant

There are two builds, chosen at build time:

- **`store`** is Google Play and the App Store. It is the default whenever nothing says
  otherwise, and it is the app exactly as it was before variants existed.
- **`fdroid`** is what F-Droid compiles.

The variant is named by `OMNIMORSE_BUILD_VARIANT=fdroid` in the environment, or by
`"omnimorse": { "buildVariant": "fdroid" }` in `package.json`. The mirror uses the second,
because F-Droid's Gradle run re-evaluates `app.config.js` and `metro.config.js` with no
environment of ours. An unknown name, or the two disagreeing, fails the build: a typo must not
silently produce the store app, Firebase and all.

### One table, every reader

`build-variant.js` holds the table of what each variant leaves out.
`src/core/domain/buildFeatures.ts` holds the same table for the app, and
`build-variant.test.ts` fails if they disagree.

| Reader | What it does with a disabled feature |
| --- | --- |
| The mirror workflow | `pnpm remove`s its packages, so neither `package.json` nor `pnpm-lock.yaml` names them |
| `app.config.js` | drops its config plugins and permissions, and ignores Firebase credential files on disk |
| `metro.config.js` | resolves its packages to an empty module, and prefers `*.fdroid.ts` twins |
| `createPorts` | never constructs its adapter; supplies a no-op or never-available one instead |
| The screens | remove its tab, rows, buttons and footnotes — gone, not greyed |

⚠️ A disabled feature is **removed**, not hidden. F-Droid's scanner and reviewers look at what is
compiled in. A flag that only hid a button would be a flag that did nothing they could see.

⚠️ `featureFlags.ts` is a different thing: kill switches for a defect found on a tester's phone,
meant to be turned back on. Build features are permanent and per build.

### What the F-Droid build keeps and loses

| Feature | F-Droid build | Why |
| --- | --- | --- |
| Text ⇄ Morse translation | **kept** | Pure JavaScript. The floor. |
| Sound | **kept** | `expo-audio` → AndroidX Media3 (Apache-2.0). Tone rendered on the device. |
| Torch / flash | **kept** | `expo-camera` → CameraX (Apache-2.0), with Google MLKit and Play Services **patched out** (below). |
| Screen flash | **kept** | Pure UI. |
| Vibration | **kept** | Local Kotlin module `modules/morse-vibration`, plus `expo-haptics`. Platform APIs only. |
| Volume check | **kept** | Local module `modules/morse-volume`. Platform `AudioManager`. |
| Tap decoder | **kept** | Pure JavaScript. |
| Text-to-speech | **kept** | `expo-speech` → platform `TextToSpeech`. Whatever engine the user installed, no network permission needed. |
| Speech input | **kept**, with `NonFreeNet` | `expo-speech-recognition` (MIT) → platform `SpeechRecognizer`. See below. |
| Learn, Tips, first-run guide | **kept** | Content. |
| Interface in EN / pt-BR / es | **kept** | |
| Crash reporting | **disabled** | Firebase Crashlytics is proprietary and named by the inclusion policy. |
| Over-the-air updates | **disabled** | `expo-updates` checks a server on launch and can replace the JavaScript F-Droid reviewed. |
| Install referrer | **disabled** (never used) | `expo-application` links Google's Play Install Referrer library; patched out. |

Speech input stays behind its own flag (`speechInput`), which the F-Droid build leaves on. If a
reviewer asks for it to go, it is a one-word edit in both tables; the Speak tab, the Translator's
Speak button, the recogniser rows in Settings and Language, the module and `RECORD_AUDIO` all
follow, and the tests already cover that state.

### Speech input and `NonFreeNet`

The library is MIT and contains no Google code. It calls `android.speech.SpeechRecognizer`, a
platform API. On most phones the service behind it is Google's, which may send audio to Google;
on others it is on-device or a FOSS recogniser the user chose.

F-Droid already ships apps that do exactly this. `com.omiyawaki.osrswiki`'s recipe says
"SpeechRecognizer is optional platform API; not a proprietary dependency" and declares
`NonFreeNet` with the text "Voice search uses the platform SpeechRecognizer, often Google
online". The draft recipe follows that precedent. `NonFreeDep` was considered and rejected:
the feature does not *require* non-free software, and the app is fully usable without it.

The app also declares a `<queries>` entry for `com.google.android.googlequicksearchbox`, written
by the library's config plugin. It is a package-visibility declaration, not code. If a reviewer
objects, the plugin takes `androidSpeechServicePackages` to change it.

## Native patches

Applied by the recipe's `init` step, after `pnpm install`, so store builds are untouched.

- **`patches/expo-camera-remove-google-mlkit.patch`** — Miroji's patch, rebuilt for
  expo-camera 57.0.4. Miroji's own no longer applies: 4 of its 6 hunks fail on SDK 57. It
  removes `play-services-code-scanner`, `mlkit:barcode-scanning` and `camera-mlkit-vision`, the
  MLKit manifest hint and the two MLKit-only files; stubs `BarcodeAnalyzer`; inlines MLKit's
  `Barcode.FORMAT_*` constants; and turns the two scanner functions into rejections. The app
  never scans barcodes. ⚠️ SDK 57 adds `expo.camera.barcode-scanner-enabled=false`, which only
  demotes the dependencies to `compileOnly`. That is not enough: they are still fetched and
  compiled against, and the scanner reads the coordinates either way.
- **`patches/expo-application-remove-installreferrer.patch`** — new. Removes
  `com.android.installreferrer:installreferrer` (Google, Play-only) and makes
  `getInstallReferrerAsync` reject. The app reads only the version from `expo-application`.
  F-Droid's own React Native template removes the same library with `sed`.

⚠️ Both patches are written against the exact `node_modules` the lockfile installs. An Expo
upgrade can break them; the recipe's `init` fails loudly when it does, and the fix is to
regenerate them the same way.

## How the mirror differs from Miroji's

| | Miroji | OmniMorse | Why |
| --- | --- | --- | --- |
| What is mirrored | the app as it is | the **F-Droid variant**: excluded packages uninstalled, then prebuilt with the variant | proprietary dependencies |
| Packaging source | patches from `main` | everything from the **tag** | the variant is app source; patches match that tag's lockfile |
| Which releases mirror | every release | plain `vX.Y.Z` only; `+metadata` tags by dispatch | `v0.3.7+appstore` would otherwise move the mirror's `v0.3.7` |
| Safety check | none | refuses to push if the generated project or lockfile names Firebase, GMS, MLKit, the referrer or `expo-updates` | |
| `hermesc` path | `react-native/sdks/hermesc/linux64-bin` | `hermes-compiler/hermesc/linux64-bin` | moved in React Native 0.86 |
| Install | `pnpm install --frozen-lockfile` | adds `--prod` | no Storybook, Stryker or Chromatic on F-Droid's server; `prepare` (husky) is dropped from the mirrored `package.json` |
| Extra files | — | `modules/`, `build-variant.js`, `metro.config.js`, `app.config.js` | local Expo modules; the variant |
| Fastlane | hand-written in the mirror, protected from sync | **generated** from `store-assets/listing/` on every run | one source of copy |
| Tests and stories | mirrored | left out | build-only snapshot |
| Network permission | stripped (`CAMERA` only) | `INTERNET` and `ACCESS_NETWORK_STATE` stripped in the F-Droid build only | the store build needs them for Crashlytics and updates |

The versionCode rule is Miroji's: `major*10000 + minor*100 + patch` from the tag, after dropping
`+metadata` the way `release.yml` does. `v0.3.7+appstore` is 307. A `-suffix` pre-release is
refused. Minor and patch must stay below 100.

## Fastlane metadata

`tools/fdroid-mirror.js fastlane` writes `fastlane/metadata/android/<locale>/` from the store
copy, for `en-US`, `pt-BR` and `es`. Spanish is written as plain `es`, not `es-419`, because
F-Droid's client matches the phone's locale and `es` is what every Spanish phone falls back to.

Limits checked, from F-Droid's
[descriptions page](https://f-droid.org/docs/All_About_Descriptions_Graphics_and_Screenshots/):
title 50, short description 80, full description 4000, changelog 500 per file.
`fdroid-mirror.test.ts` holds every locale to them.

⚠️ **The privacy paragraph is replaced.** The store copy promises anonymous crash diagnostics
and a switch for them in Settings, and says nothing you say leaves the phone. The F-Droid build
has no crash reporting and no internet permission, and speech goes to the device's recogniser.
The generator swaps in an F-Droid paragraph in each language and **fails if the store paragraph
has changed**, so the two cannot drift silently. Screenshots come from the newest
`store-assets/<version>/` set at or below the release; `f-settings.png` is left out because it
shows the crash-report switch.

**A second copy lives in this repository's `fastlane/`.** F-Droid builds from the mirror and
reads its Fastlane there, but the RFP bot and the reviewers read the `SourceCode` repository:
on rfp#4676 the bot reported "Fastlane was not found in your repo!" and a maintainer asked for
"icon, pics, txt", although the mirror had all of it. The copy is generated, never edited:
`node tools/fdroid-mirror.js source` rewrites it for the version in `app.json`, and
`fdroid-mirror.test.ts` fails when it no longer matches the listings, so **a version bump
needs that command run and committed**. Older changelogs stay, as they do in the mirror.

**The mirror's `PRIVACY.md` is the F-Droid section alone.** The full policy describes crash
reports, update checks and iOS speech recognition, none of which this build has. The section
between the `fdroid-policy` markers in `PRIVACY.md` stands alone, and
`node tools/fdroid-mirror.js privacy` writes it, with its own title and date, as the mirror's
policy. `docs/privacy-policy.html` carries the same section as number 7.

⚠️ **No field names another store.** The generator refuses Apple, App Store, iPhone, iPad, iOS,
Google Play, Play Store and Play Console in any F-Droid field. The app is judged on its own
there: the reviewer deleted the App Store link from the RFP before closing the first merge
request.

## Verification, 22–23 October 2026

All on this Windows machine, from a source tree exported with `git archive HEAD` and taken
through the workflow's steps by hand. The mirror was then installed and built outside the
repository, so no parent `node_modules` could mask a missing dependency.

- **prebuild** of the F-Droid variant succeeded. `grep` over the generated Gradle files and
  manifests found no `firebase`, `crashlytics`, `com.google.android.gms`, `google-services`,
  `installreferrer`, `mlkit` or `expo.modules.updates` after the meta-data stripper.
- **Autolinking** for Android resolves 20 Expo modules plus the two local ones. No Firebase, no
  `expo-updates`.
- **Mirror install**: `pnpm install --frozen-lockfile --prod` with `node-linker=hoisted` against
  the pruned lockfile succeeded, with real directories and no `.pnpm` farm.
- **Release APK**: `gradlew assembleRelease` succeeded, 1119 tasks, **with every Expo
  `local-maven-repo` deleted first**, so it could only pass by compiling from source. Note that
  expo-camera's prebuilt AAR was compiled *with* MLKit, which is why it has to be unused.
- **Dex** (`dexdump` over all four dex files, 26,332 classes): zero classes under
  `com/google/firebase`, `com/google/android/gms`, `com/google/mlkit`,
  `com/android/installreferrer`, `expo/modules/updates`, `io/invertase` or
  `com/google/android/play`. The `com.google.*` classes that remain are Material Components,
  Guava, Gson, Error Prone annotations and AutoValue, all Apache-2.0.
- **Permissions** (`aapt2 dump permissions`): `CAMERA`, `MODIFY_AUDIO_SETTINGS`,
  `RECORD_AUDIO`, `VIBRATE`, `WAKE_LOCK` (from AndroidX Media3, via expo-audio) and AndroidX's
  signature-level `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`. No `INTERNET`, no
  `ACCESS_NETWORK_STATE`; the merger report shows `INTERNET` rejected by the release manifest.
- **Bundle**: no `crashlytics`, no `getCrashlytics`, no `u.expo.dev`, no `expo-updates`. Two
  strings did survive the first build and were fixed: the Firebase adapter's own code (now
  replaced by a `.fdroid.ts` twin) and the update URL inside `app.json` (now stripped from the
  mirror's copy). The mirror's `app.json` has no `ios` section either: it was dead data in an
  Android tree, and its permission strings named the platform's vendor. `app.config.js` reads
  those strings with optional chaining so the F-Droid config still resolves without them.
  Bundling also works under **Node 20.19.2**, Debian trixie's version.
- **F-Droid scanner, APK**: `fdroid scanner --refresh --exit-code` on the APK (fdroidserver
  2.4.5, SUSS signatures refreshed) ran `dexdump` over all four dex files and exited 0.
- **F-Droid scanner, source**: `fdroidserver.scanner.scan_source`, the function `fdroid build`
  calls, run directly on a fresh mirror after the recipe's `init` (the `APPID` route needs a git
  clone of `Repo`, which does not exist yet). With no lists: 103 problems, **all inside
  `node_modules`, none in the mirrored source**. With the recipe's lists: **0 problems**, no
  `Unused scanignore` line, 96 files deleted by `scandelete`. **The release build then succeeded
  from what the scanner left** (1119 tasks; the APK the same size as the first build, same
  permissions, APK scan clean). That is the test that the lists are right: too little in
  `scanignore` and the build breaks, too much and the scan reports it unused.
- **Mutation**: `npx stryker run --mutate src/core/domain/buildFeatures.ts` scored 100%.

Not verified here: a build on F-Droid's own server, JDK 21 (built with Zulu 17), and the
`armeabi-v7a` ABI (built `arm64-v8a` only, to save time). F-Droid's CI on the merge request is
the place those get proven.

## The recipe draft

[fdroid/com.rogeriodocarmo.morse.yml](fdroid/com.rogeriodocarmo.morse.yml) is Miroji's recipe
adapted, with maintainer feedback from Miroji's merge request (!43165) already applied: full
commit hash, Node from Debian, JDK 21, `subdir: android/app`, no summary or description in the
recipe (Fastlane supplies them), and `useLegacyPackaging`.

⚠️ **CMake and Ninja come from Debian.** `expo-modules-core` builds native code with CMake, and
Gradle asks for exactly 3.31.6, which F-Droid's build image does not carry: the first pipeline on
!54504 stopped at `[CXX1300] CMake '3.31.6' was not found in SDK, PATH, or by cmake.dir property`.
Debian trixie (the `buildserver-trixie` image) packages `cmake` 3.31.6-2, and Gradle accepts a
CMake on `PATH` when the version matches, so `apt-get install cmake ninja-build` in `sudo` is the
whole fix. ⚠️ When an SDK bump moves the requested version, this breaks again; check what trixie
ships before reaching for anything else.

⚠️ **`react-native-worklets` gets its own JDK 21 `sed`.** Its `android/build.gradle.kts` hard-codes
Java and Kotlin 17, so once the React Native Gradle plugin is moved to 21 the two disagree. Miroji's
recipe needed the same line for the older `build.gradle` of that package (its commit "Restore
datetimepicker jvmTarget sed" put it back after it was dropped). Added before the first pipeline, on
that evidence rather than a failure seen here, since this machine builds on JDK 17.

`scanignore` keeps what the build needs and `scandelete: node_modules` removes everything else
the scanner flags. Six entries, each matched by the source scan above:

| Entry | Why the build needs it |
| --- | --- |
| `hermes-compiler/hermesc/linux64-bin` | the Hermes compiler F-Droid's Linux server runs at build time. A build tool; it never ships in the APK |
| `expo-modules-core/android/ExpoModulesCorePlugin.gradle` | Expo's Gradle plugin; flagged for `mavenLocal()` |
| `react-native/ReactAndroid/publish.gradle` | flagged for a local publishing repo |
| `react-native-safe-area-context/android/build.gradle` | flagged for the `node_modules/react-native/android` repo |
| `react-native-svg/android/build.gradle` | same. New versus Miroji |
| `@react-native-async-storage/async-storage/android/build.gradle` | flagged for a resolved module path. New versus Miroji |

Miroji's `autolinking_implementation.gradle` entry is gone: the scanner no longer flags it in
SDK 57, and an unused entry is an error.

`commit:` is `52a6b5dfb6148b97a1f5c026fb40c8a5751d51d9`, the mirror commit from the first run
(`v0.3.7+fdroid`, 24 October 2026), tagged `v0.3.7` in the mirror. ⚠️ Re-mirroring a tag rewrites
the mirror's history for it, so take the new hash from that run's job summary after any re-run.

## Privacy policy

`docs/privacy-policy.html` and `PRIVACY.md` describe Crashlytics, and the store build still does
exactly what they say, so the live policy is unchanged. Once the F-Droid build is published, add
a short section saying that build has no crash reporting, no update checks and no internet
permission, and that speech input there goes to the device's recogniser.

## What only the owner can do

In order:

1. **Create `RogerioDoCarmo/morse_app-android`** on GitHub, public, with a `main` branch, a
   README and a `.gitignore` (the sync leaves those two alone).
2. **Create the secret `MORSE_APP_ANDROID_TOKEN`** in `morse_app`: a fine-grained personal access
   token with **Contents: read and write** on `morse_app-android` only.
3. **Merge `feature/fdroid`** into `develop` and release as usual. A plain `vX.Y.Z` release runs
   the mirror. For 0.3.7, dispatch **Mirror Android Build** with tag `v0.3.7` once the workflow
   is on `main`; the tag must contain this branch's code for the variant to exist there.
4. **Check the run's summary** for the mirror commit hash, and put it in the recipe's `commit:`.
5. **Fork `fdroid/fdroiddata`** on GitLab and add the recipe as
   `metadata/com.rogeriodocarmo.morse.yml`.
6. **Open an RFP** at `gitlab.com/fdroid/rfp`, as for Miroji (#4133).
7. **Open the merge request**, saying in its description that Firebase and expo-updates are
   removed from this build and why speech input carries `NonFreeNet`.

## Risks and open questions

- **Usefulness.** Miroji's reviewer asked whether anyone would use it. F-Droid already has Morse
  apps (`rocks.poopjournal.morse`, `es.eoinrul.ecwt`). OmniMorse's case is the combination:
  four outputs, a tap decoder, speech input, a trilingual interface, and no network permission.
- **Speech.** If a reviewer reads `SpeechRecognizer` as a non-free dependency rather than a
  platform API, switch `speechInput` off. Nothing else needs to change.
- **APK size.** The local `arm64-v8a` APK is 22.8 MB. Miroji's reviewer raised size;
  `useLegacyPackaging` is already in the recipe.
- **The patches** break on an Expo upgrade, loudly. Regenerate them with the same `diff -ruN`.
- **Mirror tag moves.** Re-dispatching a tag re-points it, and the recipe hash must follow.
